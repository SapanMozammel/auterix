# Add a GraphQL Query

Delegates to the `graphql-architect` agent to design and scaffold a new GraphQL operation end-to-end (decide RSC vs Client, write `.graphql` operation, optional fragment, run codegen, scaffold the consuming component, run type-check).

## Input

Feature description: `$ARGUMENTS`

Example: `/gql-add-query "Show the 5 most recent blog posts for the current locale on the home page"`

## Process

1. **Restate the feature** in one sentence. If `$ARGUMENTS` is vague (no observable data shape, no consumer named), stop and ask the user to clarify before proceeding.

2. **Confirm endpoint state.** Check `NEXT_PUBLIC_GRAPHQL_ENDPOINT` and `schema.graphql`:
   - Endpoint set + real schema → proceed to step 3
   - Endpoint blank + placeholder schema (`type Query { _stub: Boolean }`) → tell the user this is the first GraphQL feature; the endpoint must be decided before scaffolding a real operation. Offer to scaffold a typed stub against the placeholder, OR stop until the endpoint lands. Do not silently invent an endpoint.

3. **Invoke the `graphql-architect` agent** via the Agent tool with `subagent_type: graphql-architect`. Pass the feature description verbatim. The agent reads its required-reading list (bridge skill `architecture/data-graphql.md` first, then project architecture/workflow/design-system skills, then the external `apollo-client` reference) before writing any code.

   This command does NOT bypass architecture skills. It explicitly defers all architectural decisions (RSC vs Client, auth boundary, locale handling, operation naming, fragment colocation, Suspense placement) to the agent.

4. **After the agent completes:** run `/gql-codegen` to confirm everything types. The agent runs codegen + type-check inline, so this is a redundancy check; surface any new drift.

5. **Report:**
   - Operation name + RSC vs Client decision (with the reason the agent gave)
   - Files created (`.graphql` operation, optional fragment, component skeleton)
   - Files modified (route segment if a Suspense boundary was added)
   - Codegen + type-check results
   - Manual wiring still needed (UI placement, fallback content, error UX, route-level `<PreloadQuery>` if relevant)

## Hard rules — DO NOT BREAK

- **Never bypass the agent.** The architectural decisions (RSC vs Client, auth boundary, locale handling, fragment colocation, Suspense placement) are the agent's scope. This command is a thin invocation wrapper.
- **Never invent an endpoint.** If `NEXT_PUBLIC_GRAPHQL_ENDPOINT` is unset, ask the user — the endpoint decision is a prerequisite for any real operation.
- **Never scaffold a client-side authenticated query.** The agent refuses this; if the user's feature requires `GRAPHQL_AUTH_TOKEN`, the agent forces RSC and propagates the data via props. Do not work around this.
- **Never edit files under `src/types/graphql/`** — they're regenerated by codegen.
- **Never substitute `npm` or `npx` for `pnpm`** — project is pnpm-only.

## Notes

- Operation files initially live in `src/lib/apollo/operations/*.graphql`; fragments in `src/lib/apollo/fragments/*.graphql`. Migrate next to consuming components when scope is clear.
- Apollo conventions are documented in `.claude/skills/architecture/data-graphql.md` (project-canonical); `.claude/skills/external/data/apollo-client/` is the deeper general Apollo Client 4.x reference.
- For codegen-only runs (no scaffolding), use `/gql-codegen` instead.
